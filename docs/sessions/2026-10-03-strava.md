# Session du 3 octobre 2026 : import automatique via Strava (montre Garmin)

## Décisions

- **Pas de lien direct avec la montre** : le protocole Bluetooth de Garmin est fermé (il faudrait une appli Connect IQ sur la montre). L'API officielle Garmin Connect exige un agrément professionnel et un serveur pour les webhooks. Les bibliothèques non officielles utilisent le mot de passe Garmin et contournent ses conditions : écartées.
- **Chemin retenu : Garmin Connect → Strava → Foulée.** L'utilisateur active la synchro Garmin → Strava, puis Foulée lit les courses sur Strava.
- **Sans backend** : le CORS de Strava est ouvert (vérifié par requêtes OPTIONS sur `/oauth/token` et `/api/v3/athlete/activities`). L'utilisateur crée sa propre application Strava (domaine de rappel `localhost`), colle son identifiant et son code secret dans la page Profil ; ils restent dans le `localStorage` (`foulee.strava.v1`) et **ne sont jamais dans la sauvegarde JSON**.
- **Synchro** à l'ouverture, au retour sur l'appli après plus d'un quart d'heure, et sur bouton. Pas de webhook (il faudrait un serveur).
- **Jamais de doublon, jamais d'écrasement** :
  - une course déjà importée, même supprimée ensuite, ne revient pas (liste `seen`) ;
  - une activité saisie à la main le même jour, à 10 % de distance près, est reconnue comme la même course (elle reçoit l'identifiant Strava, rien d'autre ne change) ;
  - une nouvelle course est rattachée à la séance prévue le même jour si elle n'est pas déjà faite ; avec deux sorties le même jour, la plus longue prend la séance.
- **Première synchro = tout l'historique du compte** (au départ : un mois avant le plan, ce qui ne ramenait que septembre). Un lien « Importer tout l'historique » de la carte Strava relance la lecture complète ; les courses déjà connues ou supprimées sont ignorées. Les totaux de Progrès comptent alors aussi les courses d'avant le plan.
- Seules les courses sont importées (Run, TrailRun, VirtualRun) ; durée = temps en mouvement.
- Retour OAuth protégé par un `state` aléatoire (sessionStorage) ; le code est consommé tout de suite (une seule fois, même en double rendu de développement).

## Ce qui a été fait

- `src/lib/strava.ts` (pur : conversion, fusion, fenêtre de synchro, URL d'autorisation, lecture du retour), `src/lib/stravaClient.ts` (réseau avec `fetch` injectable : échange du code, rafraîchissement du jeton, pagination, erreurs typées en français).
- `src/useStrava.ts` (hook), `StravaCard.tsx` (page Profil : mode d'emploi en 3 étapes, connexion, état, synchro, déconnexion), barre de synchro dans l'onglet Activités, mention « Strava » sur les activités importées.
- `Activity` gagne `source` et `externalId` (facultatifs, validés par `parseBackup`) ; une activité importée garde son origine quand on la modifie.
- Un nouveau plan ou un import de sauvegarde remet l'historique d'import à zéro ; « Tout effacer » déconnecte aussi Strava.
- `scripts/check-strava.ts` / `npm run test:strava` (51 vérifications avec faux `fetch`).
- Vérifié : tsc, build, sept scripts, et dans le navigateur (carte de connexion, import de courses simulées, rattachement à la séance, vélo ignoré).

## Points ouverts

- **Pas testé avec un vrai compte Strava** : l'autorisation et l'échange de jetons réels restent à essayer.
- Le code secret est stocké en clair dans le navigateur : acceptable pour un usage personnel sur son appareil, pas pour une appli ouverte à d'autres.
- Une application Strava neuve est limitée à son créateur (un seul athlète) ; quotas 100 requêtes / 15 min et 1 000 / jour.
- Si l'utilisateur modifie une course sur Strava après l'import, Foulée ne la met pas à jour.
- La fréquence cardiaque, le dénivelé et le tracé ne sont pas importés.

## Prochaines étapes possibles

1. Essayer avec un vrai compte, ajuster les messages.
2. Importer la fréquence cardiaque et le dénivelé, pour les statistiques de Progrès.
3. Si l'appli sort de l'usage personnel : petite fonction serverless pour l'échange de jetons, afin de ne plus stocker de secret côté navigateur.
