# Session du 3 octobre 2026 : profil local et sauvegarde

## Décisions

- Un seul profil local (pas de comptes ni de base de données) : prénom facultatif, sexe, âge, poids, taille, objectif. Il alimente la nutrition, et se modifie depuis une page « Mon profil » ouverte par le bouton en haut à droite du hub.
- Les données restent dans le `localStorage` (donc liées au navigateur **et au port**, d'où la perte de données constatée en changeant de port de dev). Pour répondre à « un fichier ? » : export et import d'une **sauvegarde JSON** de tout le suivi (plan, séances validées, activités, profil, journal), depuis la page Profil.
- À l'import, le fichier est entièrement validé (`parseBackup`) avant d'écraser quoi que ce soit ; une confirmation est demandée. Un fichier d'une version plus récente est refusé.
- L'écran de départ (sans plan) propose « J'ai déjà une sauvegarde : l'importer », pour un nouvel appareil.
- « Tout effacer » (avec confirmation) remet l'application à zéro.

## Ce qui a été fait

- `src/lib/backup.ts` (pur) et `npm run test:backup` (13 vérifications : aller-retour, fichiers étrangers ou corrompus, version future, valeurs par défaut).
- `ProfilePage`, bouton de profil dans l'en-tête du hub, champ prénom, lien d'import au premier lancement.
- Vérifié : tsc, build, les quatre scripts de test, et dans le navigateur : effacement, import, fichier invalide refusé sans rien modifier, enregistrement du profil.
- Bug corrigé au passage : le formulaire de profil gardait ses anciennes valeurs après un import.

## Points ouverts

- Le téléchargement du fichier n'a pas été testé dans le navigateur de l'application (seulement la logique d'export et l'import).
- La sauvegarde n'est pas chiffrée : elle contient poids, taille et âge ; à garder en lieu sûr.
- Pas de sauvegarde automatique ni de synchronisation entre appareils (il faudrait un serveur).
- L'âge est saisi, pas calculé depuis une date de naissance : à mettre à jour à la main.
